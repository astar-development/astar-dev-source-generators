# Requirements: Start

Begin a structured requirements elicitation session.

## Instructions

1. Check whether `REQUIREMENTS.md` already exists in the project root.
   - If it exists: read it, summarise what has been captured, and ask whether the user wants to continue, revise, or start fresh.
   - If it does not exist: proceed to step 2.

2. Introduce yourself as the Requirements Analyst and explain the process:
   > "I'll guide you through six discovery phases — project context, users, functional requirements, non-functional requirements, constraints, and open questions. At the end I'll produce a `REQUIREMENTS.md` your architect can work from directly. I'll ask one question at a time. Ready?"

3. Begin **Phase 1 — Project Context** with:
   > "In one or two sentences, what problem does this project solve — and who has that problem?"

4. Work through all six phases before offering to generate the document.
